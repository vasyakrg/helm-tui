# helm-tui Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Терминальный UI на Go для просмотра и управления helm-репозиториями, поиска чартов/версий и diff двух версий чарта.

**Architecture:** Бинарь `helm-tui`. Управление repo идёт через подпроцесс `helm` (интерфейс `helm.Runner`), версии/даты/число чартов читаются read-only из `index.yaml` в кэше helm. Доступность проверяется HTTP-запросом через прокси repo. Diff: `helm pull --untar` обеих версий в `/tmp/helm-tui-<id>` и сравнение деревьев. TUI — стек экранов на Bubble Tea.

**Tech Stack:** Go (текущий на хосте), `charm.land/bubbletea/v2`, `charm.land/bubbles/v2` (textinput), `charm.land/lipgloss/v2`, `gopkg.in/yaml.v3`, `github.com/Masterminds/semver/v3`. Точные import-пути проверить `go get` (Context7: Bubble Tea v2.0.0 и Bubbles v2.0.0 существуют). Библиотеку построчного diff выбирает исполнитель.

**Spec:** `docs/superpowers/specs/2026-11-02-helm-tui-design.md`

## Global Constraints

- Хост: Helm v4.3.1, macOS. JSON helm v4: `repo list -o json` → `name,url`; `search repo -l -o json` → без дат. Даты/версии/число чартов только из `<HELM_REPOSITORY_CACHE>/<repo>-index.yaml` (путь из `helm env`).
- Запись в `repositories.yaml` только через `helm`. Старт не делает `helm repo update`.
- Не поддерживаются: OCI-реестры, TLS/CA-флаги repo, Keychain, fuzzy-поиск, вложенная распаковка `charts/*.tgz`.
- Любая сетевая операция имеет таймаут; проверка доступности ~5 с, параллельно, с прокси этого repo.
- Статусы: `…` проверяется, `●` доступен (мс), `✕` недоступен с причиной (timeout, DNS, TLS, 403, proxy error).
- Прокси: `http://`, `https://`, `socks5://`; свой на каждый repo; конфиг `~/.config/helm-tui/config.yaml`, файл 0600, каталог 0700; пароль открытым текстом (принято). Для repo с прокси подпроцесс получает `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY`, `NO_PROXY` очищается; без прокси окружение наследуется как есть.
- Пароль repo — только `helm repo add --password-stdin`, никогда в argv.
- Пароли прокси и repo не попадают в UI, логи и тексты ошибок (маскируются).
- Diff: каталог `/tmp/helm-tui-<id>` с файлом `pid`; удаляется при выходе из Diff и при завершении (в т.ч. по сигналу); при старте удаляются каталоги упавших запусков. Версия A = меньший semver, B = больший; `+` = есть в B. Бинарные файлы и `*.tgz` — «изменён» без содержимого. Только один chart одного repo.
- Глобальный поиск: регистронезависимая подстрока по имени чарта и описанию, один результат на чарт (последняя версия), Enter раскрывает версии.
- Название модуля `github.com/vasyakrg/helm-tui`, бинарь `helm-tui`, `origin` = `git@github.com:vasyakrg/helm-tui.git` (push не делать без просьбы).

## Review Focus

Не покрыто явно спецификацией, но укусит пользователя (вход → ожидаемое поведение). Тест для каждого пункта лежит в задаче-владельце:

1. `helm repo list` при нуле repo (helm выходит с ошибкой «no repositories») → пустой список с подсказкой `a`, без падения. (Task 3)
2. Repo в конфиге без файла индекса в кэше (реальный `authentik`) → «—» в таблице, нет в поиске, на экране Charts сообщение. (Task 5, Task 10)
3. Версии не по semver / дубликаты в индексе → без паники, детерминированный порядок, нестандартные в конце. (Task 5)
4. Отмена (Esc, Ctrl+C, SIGTERM) во время `helm pull` → подпроцесс убит, `/tmp/helm-tui-*` удалён. (Task 8)
5. Пароль прокси/repo в тексте ошибки `helm` или http-клиента → замаскирован. (Task 2, Task 3, Task 6)
