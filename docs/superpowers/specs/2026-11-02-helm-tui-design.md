## Зачем

Хост пользователя использует много helm-репозиториев (9 штук: traefik, kyverno, grafana, vm, prometheus-community, argocd, openebs-cstor, rancher-stable, stackrox). Стандартный `helm repo` неудобен для обзора и управления ими, а часть источников периодически блокируется. Нужен терминальный UI, где можно:

1. Видеть список источников и их доступность.
2. Управлять ими (добавить, удалить, обновить).
3. Искать чарты и версии, в том числе сразу по всем источникам.
4. Сравнивать две версии одного чарта и видеть, что изменилось.

## Цели

- TUI для просмотра и CRUD над helm repo. [сказано]
- Поиск внутри repo и глобальный по всем repo. [сказано]
- Проверка доступности источников при старте. [сказано]
- Прокси, свой на каждый repo. [сказано]
- Diff двух версий одного чарта: весь diff целиком (`Chart.yaml`, `values.yaml`, `templates/`, `crds/`, зависимости), версии пуллятся локально в `/tmp`. [сказано]
- Раскладка «экраны по очереди» (drill-down): Repos → Charts → Versions → Diff, Esc возвращает назад. [сказано]
- Go + Bubble Tea, один бинарь. [моё]
- Утилита вызывает `helm` подпроцессом и не пишет в `repositories.yaml` напрямую. Источник правды один — конфиг helm. [моё]

## Не цели

- Не заменяет helm: нет install/upgrade/uninstall релизов, нет работы с кластером. [моё]
- Не хостит и не зеркалирует чарты. [моё]
- Не поддерживает OCI-реестры (`helm registry`). Только классические http(s)-репозитории с `index.yaml`. [моё]
- Не меняет глобальные переменные окружения пользователя. [моё]

## Анти-цели (что считается провалом, даже если работает)

- Утилита портит или переписывает `repositories.yaml` не через `helm`. [моё]
- Зависание UI при заблокированном repo (любая сетевая операция должна иметь таймаут). [моё]
- Пароли или токены прокси и repo видны в UI, логах или сообщениях об ошибках. [моё]
- Остаются мусорные каталоги в `/tmp` после выхода. [моё]

## Экраны

### 1. Repos (стартовый)

Таблица: имя, URL (без учётных данных), число чартов, статус доступности, прокси.

| Клавиша | Действие |
|---|---|
| `a` | добавить repo (форма: name, URL; username и password опциональны [моё]) → `helm repo add` |
| `d` | удалить (с подтверждением) → `helm repo remove` |
| `u` | обновить выбранный → `helm repo update <name>` |
| `U` | обновить все |
| `p` | задать или снять прокси для выбранного repo |
| `r` | перепроверить доступность |
| `/` | глобальный поиск по всем repo |
| Enter | открыть чарты repo |
| `q` | выход |

### 2. Charts

Чарты выбранного repo с поиском по `/`. Enter открывает версии.

### 3. Versions

Версии чарта с датой и appVersion. Пробел отмечает версию (максимум две). `D` запускает diff для двух отмеченных.

### 4. Diff

Слева список файлов с пометками: изменён `~`, добавлен `+`, удалён `-`. Справа построчный diff выбранного файла. `j/k` выбор файла, `n/N` переход между hunk, Esc возвращается к Versions.

### Глобальный поиск

Вызывается с экрана Repos. Ищет по локальному кэшу индексов всех repo (аналог `helm search repo`). Результат: repo, чарт, версия. Enter переходит к версиям найденного чарта. Работает и для заблокированных repo, если индекс скачан ранее. [сказано в части глобальности, остальное моё]

## Проверка доступности

- Запускается при старте параллельно для всех repo. Экран открывается сразу, статусы подтягиваются по мере ответов. [сказано: проверка при старте]
- Проверка: HTTP-запрос к `<url>/index.yaml`, таймаут около 5 секунд, учитывает прокси этого repo. [моё]
- Статусы: `…` проверяется, `●` доступен (задержка в мс), `✕` недоступен с причиной (timeout, 403, DNS, TLS, proxy error). [моё]
- Недоступный repo остаётся в списке и в глобальном поиске по кэшу. Операции `u` и `helm pull` для него завершаются понятной ошибкой, не зависают. [моё]

## Прокси

- Свой прокси на каждый repo. [сказано]
- Хранится в конфиге утилиты `~/.config/helm-tui/config.yaml` (права 0600), отдельно от helm. [моё]
- Форматы: `http://`, `https://`, `socks5://`, опциональные учётные данные в URL. [моё]
- Реализация: при вызове `helm repo update` / `helm pull` для данного repo прокси подставляется в окружение подпроцесса (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` при необходимости). Проверка доступности использует тот же прокси. Пользовательское окружение не меняется. [моё]
- В UI пароль прокси маскируется. [моё]

## Diff

1. Для выбранных версий A и B выполняется `helm pull <repo>/<chart> --version <v> --untar --untardir /tmp/helm-tui-<id>/<v>` (с прокси repo, если задан). [сказано в части /tmp и пулла]
2. Деревья сравниваются целиком, включая `Chart.yaml`, `values.yaml`, `templates/`, `crds/`, `charts/`. [сказано]
3. Каталог `/tmp/helm-tui-<id>` удаляется при выходе из экрана Diff и при завершении программы (в том числе по сигналу). [моё]
4. Ошибка пулла одной из версий показывается в UI, частичный diff не строится. [моё]

## Конфигурация и данные

- Список repo читается через `helm repo list -o json`, чарты и версии через `helm search repo -l -o json`. [моё]
- Пути к конфигу helm берутся из `helm env` / стандартных переменных (`HELM_REPOSITORY_CONFIG` и т.п.), так что нестандартные настройки пользователя работают. [моё]
- Конфиг утилиты: только прокси по именам repo. [моё]

## Уточнения по итогам проверки (все [моё], проверено на хосте)

- **Слой данных.** Проверено на Helm v4.3.1: `helm repo list -o json` даёт `name`, `url`; `helm search repo -l -o json` даёт `name` (`repo/chart`), `version`, `app_version`, `description`, **без даты**. Поэтому: список repo идёт через `helm`, а версии, даты (`created`) и число чартов читаются **read-only** из `<HELM_REPOSITORY_CACHE>/<repo>-index.yaml` (путь из `helm env`). Запись в кэш делает только `helm repo update`.
- **Repo без индекса в кэше.** Реальный случай: `authentik` есть в конфиге, но `authentik-index.yaml` отсутствует (`helm` пишет `repo is corrupt or missing`). Такой repo показывается с «—» вместо числа чартов, в поиск не попадает. Старт **не** делает `helm repo update` сам, только проверяет доступность.
- **Прокси и `add`.** В форме добавления есть поле прокси; оно применяется к самому `helm repo add`, иначе заблокированный источник не добавить.
- **Прокси: окружение.** Если у repo прокси задан, он перезаписывает `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` подпроцесса, а `NO_PROXY` очищается для него. Если не задан, подпроцесс наследует окружение пользователя без изменений. Пароль прокси в окружении дочернего `helm` виден только тому же пользователю (`ps eww`); избежать этого при работе через `helm` нельзя, риск принимается и фиксируется в отчёте.
- **Пароль repo.** Передаётся в `helm repo add` через `--password-stdin`, не через argv.
- **TLS/CA-флаги repo** (`--insecure-skip-tls-verify`, `--ca-file`, client cert) в первой версии не поддерживаются. [сказано: свои CA пока не поддерживаем]
- **Пароль прокси** хранится в файле конфига открытым текстом с правами 0600 (как `helm` хранит пароли repo), без Keychain. [сказано: «пароль через файлы, не усложняем»] Риск (чтение файла любым процессом пользователя) принят явно и фиксируется в отчёте.
- **Репозиторий проекта:** `origin` = `git@github.com:vasyakrg/helm-tui.git`. [сказано]
- **Diff.** Старая версия (A) — меньший semver, новая (B) — больший, независимо от порядка отметки; `+` значит «есть в B». Бинарные файлы и `charts/*.tgz` показываются как «изменён», без распаковки вложенных архивов. Сравниваются только версии одного чарта одного repo. Кэша распакованных версий между запусками нет.
- **Уборка `/tmp`.** При старте удаляются устаревшие каталоги `/tmp/helm-tui-*` от упавших запусков (владелец процесса из файла `pid` в каталоге уже не жив).
- **Глобальный поиск.** Регистронезависимая подстрока по имени чарта и описанию; один результат на чарт (последняя версия), Enter раскрывает все версии. Fuzzy в первой версии нет.
- **Версии зависимостей.** Актуальные версии Go и Bubble Tea (v1 или v2) исполнитель выбирает сам по документации Context7.
